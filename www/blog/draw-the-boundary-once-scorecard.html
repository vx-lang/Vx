Draw the boundary once: the scorecard

Aditya Kumar · 27 October 2026

This page holds the evidence for the scores in Draw the boundary once. Each table gives the score, the reason and a source for one pair of compiler and build system. The scores are as of 25 October 2026.

The six tests come from the equation in the post:

  1. Function: the compile and the build read only declared inputs.
  2. Interface: a dependent compile reads only an interface file, and nothing in that file is inferred from a function body.
  3. Cutoff: a change to a private item or a function body rebuilds no other package.
  4. Graph: the build system learns the package graph without scanning source files.
  5. Visibility: what is visible does not depend on what the build tool compiles together.
  6. Bump: the package manager computes the version bump from the interface diff.

✓ passes, ◐ passes in part, ✗ fails, – does not apply. None of the 16 pairs passes all six tests.

Elm (elm make, elm publish): 4 of 6

TestScoreReasonSource
Function◐No compile-time code, and packages cannot use ports or kernel (JavaScript) code. A package build solves its version ranges against the registry, with no lock file.Parse/Module.hs, Elm/Details.hs, ports guide
Interface✓Package docs reject exposing (..) and any exposed value without a type annotation. Modules inside an application can still have inferred interfaces.Elm/Docs.hs, Error/Docs.hs
Cutoff✓The build compares the new .elmi with the old one and keeps dependents cached when they match. The .elmi holds only exposed values.Build.hs, Interface.hs
Graph◐elm.json gives the package graph, but the build parses each source file for its imports.Build.hs
Visibility✓The module's exposing list and exposed-modules set visibility. Two files for one module name are an error.Interface.hs
Bump✓elm publish diffs the old and new API and refuses a version number that does not match.Publish.hs

Java + Bazel: 4 of 6

TestScoreReasonSource
Function◐The sandbox shows an action only its declared inputs. Processes can still read the host file system, and the network is allowed by default.Sandboxing, command-line reference
Interface✓Dependents compile against header jars. Turbine and ijar remove method code and private members.Turbine RemovePrivateMembers, ijar README
Cutoff✓Skyframe skips dependents when a rebuilt value did not change, so A recompiles only when the header jar of B changed.Skyframe, compiler-dev mail
Graph✓deps in BUILD files.Java rules
Visibility✓Java access is set in source. Bazel's visibility attribute adds a declared gate at the target level.Visibility
Bump✗Bazel modules have versions, but the docs say the bump semantics “are not enforced”.Modules

Java + Gradle: 3 of 6

TestScoreReasonSource
Function✗Build scripts are code that can read environment variables and files, and tasks are not sandboxed.Configuration cache, incremental build
Interface◐Java signatures are written out, but javac reads the full class files of the dependency.Java library plugin
Cutoff✓Compile avoidance ignores method bodies and private members. Package-private members and constants stay in the hash.Compile avoidance
Graph✓From declared dependencies, although the build file is code.Build lifecycle
Visibility✓Java access is set in source. api and implementation are declared in the build file.JLS 6.6
Bump◐Only the third-party tool japicmp suggests the bump.japicmp

Rust + Cargo: 2 of 6

TestScoreReasonSource
Function✗build.rs and procedural macros can read any file or environment variable. The API that tracks such reads is nightly-only.Build scripts, proc_macro::tracked
Interface✗Auto traits such as Send leak through -> impl Trait and async fn, so the body decides part of the interface.RFC 1522
Cutoff✗A crate's fingerprint includes the input hashes of its dependencies, so any change in a dependency recompiles its dependents. Early cutoff is an open issue.fingerprint/mod.rs, cargo#17439
Graph✓Cargo.toml and Cargo.lock. Targets such as src/bin/* are still found by directory layout.Specifying dependencies, targets
Visibility✓Visibility follows the module tree from mod declarations, starting at the crate root.Visibility and privacy
Bump◐Only cargo-semver-checks, a separate tool. Moving it into cargo publish is a 2026 project goal.Project goal

Rust + Buck2: 2 of 6

TestScoreReasonSource
Function◐Buck2 runs build.rs as an action with an explicit environment, but it does not sandbox local actions.cargo_buildscript.bzl, Buck2
Interface✗It uses the same rustc metadata as Cargo.build_params.bzl
Cutoff✗The DICE engine has early cutoff, but .rmeta changes on every source edit, so the cutoff cannot fire. A test with rustc 1.95.0 showed this for a private function body.DICE incrementality
Graph✓BUCK files declare dependencies. Reindeer generates them from Cargo.toml.Buck2
Visibility✓The same Rust module tree as Cargo.Visibility and privacy
Bump✗No semver step in Buck2 or Reindeer.Reindeer manual

Rust + Bazel (rules_rust): 2 of 6

TestScoreReasonSource
Function◐Actions are sandboxed, but the network is allowed by default, and build scripts get the default shell environment.Sandboxing, rules_rust settings
Interface✗It uses the same rustc metadata as Cargo.RFC 1522
Cutoff✗Pipelined compilation is off by default, so dependents read the whole .rlib. With it on, .rmeta still changes on every edit.Skyframe, rules_rust settings
Graph✓BUILD files declare every direct dependency.Dependencies
Visibility✓The same Rust module tree, and srcs is listed explicitly.Visibility and privacy
Bump✗No semver feature.Modules

C++ headers + Bazel: 1 of 6

TestScoreReasonSource
Function◐The same sandbox limits as Java + Bazel: the host file system stays readable, and the network is allowed by default.Sandboxing
Interface✗Dependents compile the headers, which hold private members and inline and template bodies. An auto return type comes from the body.C/C++ rules, cppreference: function
Cutoff◐A change to a .cc file does not recompile dependents. Any header edit does, even to a private member.Skyframe, command-line reference
Graph✓Headers are declared in hdrs and srcs. Include scanning is off by default.C/C++ rules
Visibility◐Keeping srcs headers private needs clang's layering_check, and it covers direct includes only.C/C++ rules
Bump✗The same as Java + Bazel.Modules

C++20 modules + CMake and Ninja: 0 of 6

TestScoreReasonSource
Function✗Ninja has no sandbox, and it learns headers from compiler depfiles by timestamp. CMake takes the compiler from the CXX environment variable.Ninja manual, CMake: CXX
Interface◐Importers read a compiled module interface (BMI), but Clang may open the input files of a BMI. Reduced BMIs, without non-inline bodies, became the default only in Clang 22.Clang: C++ modules
Cutoff◐CMake documents that compilers rewrite the BMI on every compile, so any edit to an interface unit recompiles all importers. An implementation unit has no BMI.cmake-cxxmodules
Graph✗CMake scans the sources during the build (P1689 format) and feeds the result to Ninja.cmake-cxxmodules
Visibility◐export is in the source. But Clang alone decides whether internal partitions are reachable, and CMake does not check private module sets.Clang: C++ modules, cmake-cxxmodules
Bump✗The author picks the compatibility mode by hand.CMakePackageConfigHelpers

Kotlin + Gradle: 1 of 6

TestScoreReasonSource
Function✗The same as Java + Gradle: build scripts are code, and tasks are not sandboxed.Incremental build
Interface✗A single-expression function takes its return type from the body unless explicit API mode is on.Functions, What's new in 1.4
Cutoff◐The Kotlin compiler runs after every change in a dependency. ABI snapshots then limit what recompiles. Inline bodies and const val values count as ABI.JetBrains blog, 2022
Graph✓The same as Java + Gradle.Build lifecycle
Visibility✗internal means “a set of Kotlin files compiled together”, such as a Gradle source set.Visibility modifiers
Bump◐The experimental ABI validation fails on an ABI change but ignores the version number.Binary compatibility validation

Go + the go command: 0 of 6

TestScoreReasonSource
Function◐Go has no build scripts or compile-time code. But cgo reads CC, CGO_CFLAGS and pkg-config, and the go command finds go.work from the current directory.cgo, Modules reference
Interface◐Dependents read export data. It carries the bodies of inlinable and generic functions, and of unexported helpers they reach.noder/linker.go, generics design
Cutoff✗Go 1.27 keys a dependent on a hash of the whole archive, object code included. A key on export data landed on the development branch in August 2026 and is not released. Export data also records line positions.exec.go, Go 1.27, commit 1dacc62658, go#15752
Graph✗The package graph comes from the import lines of each source file. go.mod gives only the module requirements.imports/read.go
Visibility✗The spec leaves the set of files in a package to the tool, and internal/ is a rule about directory paths.Go spec, cmd/go
Bump◐gorelease suggests a version, but it is experimental and nothing enforces it.gorelease

Zig + zig build: 1 of 6

TestScoreReasonSource
Function✗build.zig is arbitrary code with access to the environment and the file system. The compiler itself is pure: comptime cannot call external functions.std/Build.zig, 0.17.0 release notes
Interface✗A project is one compilation of all modules from source. An inferred error set takes part of the return type from the body.Language reference
Cutoff✗By default, any change reruns the whole compilation. Incremental compilation per declaration needs -fincremental.Compilation.zig, 0.17.0 release notes
Graph◐build.zig.zon lists packages as data, but the module graph exists only after build.zig runs.build.zig.zon
Visibility✓A declaration without pub stays in its file, and files join only by @import.import outside module path
Bump✗version is a string that nothing checks.build.zig.zon

Nix: 1 of 6

TestScoreReasonSource
Function◐On Linux, a build sees only its store inputs and has no network. Fixed-output derivations keep the network, and the sandbox is off by default on other systems.nix.conf
Interface✗Inputs are whole outputs of other derivations. There is no interface.Derivations
Cutoff✗An output path hashes the derivation of each dependency, so any change rebuilds every dependent. Content-addressed derivations are experimental and need bit-identical outputs.Input addressing, experimental features
Graph✓All inputs are declared. Import-from-derivation is the exception.Derivations, import from derivation
Visibility–Nix has no item visibility. The compiler it wraps decides.Derivations
Bump–Dependencies are pinned by hash, with no version ranges.Derivations

OCaml + dune: 0 of 6

TestScoreReasonSource
Function✗A preprocessor's file inputs count only if the author lists them. Dune's sandbox is opt-in and keeps the environment variables.Sandboxing, preprocessing
Interface◐Dependents read the .cmi, which can come from a hand-written .mli. Without one, the types are inferred. Native code also reads .cmx unless -opaque is set.Batch compiler, native compiler
Cutoff◐The dev profile uses -opaque and content hashes. The release profile, which opam uses, drops -opaque. A .cmi also records the digests of every interface it imported.Profiles, persistent_env.ml
Graph◐libraries gives the library graph, but ocamldep scans the sources for module dependencies.ocamldep, Discuss report
Visibility◐The .mli sets visibility. But a library's modules default to every file in its directory.library stanza
Bump✗opam has no semver rule and no API check.opam manual

Haskell GHC + Cabal: 0 of 6

TestScoreReasonSource
Function✗Template Haskell runIO can do any IO at compile time, and declaring the files it reads is opt-in. A custom Setup.hs runs arbitrary code.Template Haskell, package description
Interface◐Top-level type signatures are optional, and above -O0 the .hi carries function bodies.Warnings, optimisation
Cutoff◐GHC keeps a fingerprint per declaration. But Cabal builds with -O1 by default, so a body change reaches dependents.Separate compilation, cabal.project
Graph◐build-depends gives the package graph. ghc --make follows the imports to find modules.Separate compilation
Visibility◐Export lists set visibility, but GHC can pick up a module from disk that the package does not list.Warnings
Bump✗The PVP states the rules, but Hackage does not check them.PVP

Swift + SwiftPM: 0 of 6

TestScoreReasonSource
Function✗Package.swift can read every environment variable and the git status as official API. The macOS sandbox allows every file read.Context.swift, Sandbox.swift
Interface◐Dependents read a .swiftmodule. Library evolution is off by default, so clients see every layout. The concrete type behind some P comes from the body.SE-0260, SE-0244
Cutoff◐Debug builds use fingerprints across modules. Release builds compile each module whole, and a change to a private stored property is an interface change.swift-driver, SwiftModuleBuildDescription
Graph◐Targets come from the manifest. But an undeclared import compiles if an earlier build left the module behind.Options.swift, forum thread
Visibility✗internal means the module, and the module is whatever files the build target holds.Access control, Target.swift
Bump◐swift package diagnose-api-breaking-changes exists. It is optional, and it reports breaks without computing the bump.Documentation

Vx today: 0 of 6

Scored from the compiler source on main at commit e66345d3. The post describes the design. This table describes what is built.

TestScoreReasonSource
Function✗The compiler reads 19 environment variables, and 15 of them can change the program it builds or the tool that builds it. It finds z3 and the LLVM tools through PATH. Without VX_STD_PATH, it looks for the standard library beside the compiler, then in the current directory.module_loader.rs, jit.rs, solver.rs, VxLowering.cpp
Interface◐A signature is the whole contract, and vxc --emit-interface writes a .vxlib interface file. The file also carries function bodies, and the parallel compile (-j) does not read it yet.driver.rs
Cutoff✗There is no build system yet, so nothing skips a rebuild.
Graph◐Each package is passed as --package name=dir. There is no manifest yet.driver.rs
Visibility◐pub and private items exist, but pkg and ws are not built. Imports resolve through search paths that include the current directory.module_loader.rs
Bump✗There is no package manager yet.
