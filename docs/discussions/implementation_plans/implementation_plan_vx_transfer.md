# Implement Memory Transfer Op (`vx_transfer`) and RAII Semantics

This document outlines the plan to finalize the first pillar of the NPU execution model: strict, explicit data transfers (`vx_transfer`) and RAII-style memory management to ensure zero memory leaks across device boundaries.

## Background Context

Currently, the compiler permits implicit conversions between `Ref<T>`/`Pinned<T>` and `T` (e.g. Host Memory implicitly assigning to NPU Memory representations). This causes opaque performance characteristics and potential correctness bugs. We must force explicit `transfer(...)` intrinsic calls when moving tensors across memory topologies.

Additionally, memory allocations (`memref.alloc` generated by `transfer`) currently do not have explicit destructors. We want RAII semantics: when an allocated tensor goes out of scope (e.g. end of block, `return`, or block exit), a `memref.dealloc` must be automatically emitted.

## User Review Required

> [!WARNING]
> **Breaking Change:** Disabling implicit memory conversions will break any existing code that assigns a `Ref<T>` (from another memory space) directly to `T`. Such code must be updated to use the explicit `transfer(expr, Memory::Space)` syntax.

## Proposed Changes

### Semantic Analysis

#### [MODIFY] `src/sema.rs`

- **Disable Implicit Memory Coercion:** Remove the implicit unwrapping of `Type::Ref(inner_source, _)` and `Type::Pinned(inner_source, _)` when determining if `target` and `source` are assignable inside `fn is_assignable`.
- **Require Explicit Casting:** Update the compiler errors to guide users towards `transfer(expr, Memory::NPU_HBM)` or `transfer(expr, Memory::Host_DRAM)` when assignments fail due to memory topology mismatch.

### MLIR Codegen (RAII Memory Management)

#### [MODIFY] `src/melior_codegen.rs`

- **Track Allocations per Scope:** Introduce a mechanism to track variables bound to `memref.alloc` pointers within the current lexical block scope (e.g. `self.active_allocations: Vec<Vec<Value>>`).
- **Emit `memref.dealloc`:**
  - Hook into `lower_block` or `lower_statement` such that before a block naturally terminates, we iterate over the active allocations in the current scope and emit `memref.dealloc`.
  - Hook into `ReturnStmt` to ensure all active allocations across *all* active block scopes are deallocated before emitting `func.return`.

## Verification Plan

### Automated Tests

- **Fail Tests:** Add tests to `tests/backend/fail/` that attempt to assign a `Ref<Tensor>` to a `Tensor` without `transfer()`. Expect the semantic analyzer to reject it.
- **Pass Tests:** Add tests to `tests/backend/pass/` that explicitly use `transfer(...)` and verify that the generated MLIR contains `memref.dealloc` calls before the `func.return` by parsing the `.vxm` output using `FileCheck`.

### Manual Verification

- We will visually inspect the generated `output.vxm` MLIR code for `memref.dealloc` calls at block exit points.
